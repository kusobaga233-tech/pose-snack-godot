# Core model (pure GDScript rules)

Reference implementation: the Web prototype at
`D:\CODEX-PROJ\yoodou\pose-snake-full-20261112\pose-snake` (`js/snake.js`,
`js/game.js`, `js/ai.js`). This file records the parts of that model the tests
pin down and the deliberate deviations.

The rules live in `src/core/**` and are headless: no `Node`, no `Timer`, no
`Tween`, no rendering, and no wall clock. `PSGame.update(dt, signal, real_dt)` is
the only entry point.

## Motion

Per frame, for a snake with a control (`js/snake.js` `update()`):

```
target    = control.angle + control.wobble        # wobble is 0 for humans
diff      = norm_angle(target - heading)
rate      = tuning.turn_rate * control.turn_ease * turn_mul
boost     = 1 + (abs(diff) / PI) * (turn.reverse_boost - 1)
max_turn  = rate * boost * dt
turned    = clamp(diff, -max_turn, max_turn)     # js/snake.js line 263
heading   = norm_angle(heading + turned)
turn_amount = abs(turned)
```

Consequences the tests rely on:

* A target **inside** the cap is followed exactly: `turned == diff`, so a
  0.1 rad wobble produces a 0.1 rad turn (`turn_amount == heading == 0.1`).
  `max_turn(0.1) == 0.14324495318566127` is only the *ceiling*, not the turn.
* A target **beyond** the cap (e.g. 0.2 or 0.5 rad at the default 8.5 rad/s)
  is clamped to `max_turn`; that is the actual "turn cap" behaviour.
* `turn_ease` is AI-only (`PSBrain.AI_TURN_EASE`), humans use 1.0, and the
  boost grows linearly with `|diff|/PI` up to `turn.reverse_boost`.

Numbers are regenerated by `node tests/reference/js_reference.mjs`
(`turn.*`, `turn.*.applied`) directly from `js/config.js` + the JS `clamp`.

Speed (`updateSpeed`, `js/snake.js`):

```
speed = base_speed * speed_mul
        * (1 - slow_strength * (1 - e^(-extra / slow_scale)))
        * boost_multiplier() * clamp(pose_speed, pose.speed.min_limit, max_limit)
```

`extra = max(0, length - start_segments)`, so "bigger is slower" is recomputed
every frame. The body is a follow chain: node `i` is pulled towards `i-1` only
when the link is longer than `snake.seg_dist`; the radius is a pure function of
length and the girth slider (`PSConfig.snake_radius`).

## Clock

`now` is written by `PSGame` once per frame from the simulation clock. All
timers (`freeze_until`, `immune_until`, buff seconds) are measured against it,
never against `Time.get_ticks_msec()`. `real_dt` only drives countdowns (round
timer, respawn timers, buffs) so a hit-stop cannot stretch them.

## Determinism contract

Same seed + same input log ⇒ identical world state, byte for byte. The update
path must not use:

* Godot's global RNG (`randf()`, `randi()`, `randomize()`),
* wall-clock APIs (`Time.*`, `OS.get_ticks_*`, `Engine.get_process_frames`),
* hash-order iteration of `Dictionary`/`Set` (only stable arrays are iterated),
* frame-time-dependent sampling without passing `dt`.

Randomness is injected through `PSRng` (xorshift32) only:

| Stream | Owner | Consumers |
| --- | --- | --- |
| `PSGame.rng` | world | food spawns, respawn points, AI speed jitter, cosm. wave phase |
| `PSGame.round_rng` | round | style + head-style shuffles (re-seeded per round) |
| `PSGame.powerup_rng` | powerups | powerup type/position only |
| one per `PSBrain` | AI | skill, lapses, aim noise, wobble, sloppy food picks |

### GDScript trap (fixed 2026-11-12)

Inside a class method, a **bare** call to `randf()` resolves to Godot's global
built-in `randf()`, not to a method of the same name on the class. `PSRng`
defines its own `randf()`, so every `rand_range()` / `rand_int()` draw silently
came from the engine RNG (different every run) while the injected stream never
advanced. The determinism suite caught it as: identical post-construction RNG
states but different AI spawns/skills. Fix: `self.randf()` inside `PSRng`.
Regression guards live in `suite_determinism` ("rand_range is reproducible",
"rand_range consumes exactly one seeded draw", "rand_int is reproducible").

Verify:

```
tools\run_suites_sequential.ps1 -PerSuiteTimeoutSeconds 60   # per suite
tools\run_godot_safe.ps1 -Script res://tests/run_all.gd -TimeoutSeconds 180
```

`tests/_probe_det.gd` prints the full state signature of two independent
same-seed runs (`SIG_A`, `SIG_B`); two consecutive invocations must produce
byte-identical stdout.

## Deviations from the JS prototype

* `PSRng` is xorshift32, not V8's `Math.random()`: reproducible run-to-run, but
  not bit-identical to a browser session (see `rng.gd`).
* Respawn freeze / immunity / buff timers use the simulation clock instead of
  `performance.now()` (a slow frame in JS could stretch the freeze).
* `ensure_food()` trims a pellet: the port also clears AI references to it
  (`forget_target`), where JS left a dangling target for up to one retarget.
* `STATE_COUNTDOWN` is a port-only state for the 3-2-1 shell countdown; `start()`
  without an argument still goes straight to `STATE_PLAYING` like JS.
* Collision/rendering split: the sine wobble exists only in `render_points()`,
  never in the collision chain.
* **Self-collision is harmless (2026-11-12).** The JS prototype kills a snake whose
  head touches its own body (`js/game.js` `resolveCollisions()` step 1). The port
  gates that branch behind `cfg.collide.self_kill`, default `false`: the overlap is
  a complete no-op — no death, no respawn timer, no corpse scatter, no kill/score,
  no immunity and no presentation event, and the head is not even clamped. Walls
  and every enemy rule (body collision, head-on length arbitration, side-on ram,
  immunity/freeze) are untouched. `self_kill = true` restores the prototype
  behaviour, including the forgiving `ai.self_hit` skip/radius window for AI, so
  the old rule stays reachable for tests and side-by-side comparison.
  The AI's `ai.self_avoid` heuristics still run (they keep the paths looking
  natural and are now purely cosmetic); no AI or power-up logic reads a
  self-death, so nothing waits on an event that no longer fires.
  Both modes are pinned by `tests/suite_collisions.gd` ("self collision no
  longer kills", "600 frames of self overlap never kill", "the tight curl
  survives 15 s", "self_kill = true restores the prototype self-death").
  Measured with `tests/_probe_self_rule.gd` on the `suite_round` sweep
  (seed 302, full 120 s): 37 deaths = 25 enemy collisions, 12 walls, **0 self**;
  4 snakes spent 54 snake-frames with the head inside their own body and simply
  kept playing. The same probe shows a side effect worth knowing: at the shipped
  `turn.rate = 8.5` the 18 px follow chain cuts the corner so hard that a snake
  turning constantly orbits *inside* its own coil (nearest own node 52-72 px,
  never a hit); at 2.2 rad/s (just above the `turn.rate_min` = 2.0 slider floor)
  the body tracks the loop and the head really does cross it (77 of 900 frames).
